# 机械臂自主观察与调试

用户给出观察、移动、测试或抓取目标后，持续完成该目标。用户授权自由发挥时，根据新鲜画面自主选择观察方向、步长、速度和结束姿态。已有授权足够时直接执行，普通动作和扩大观察范围无需逐次确认。结合当前空间、机械状态与用户最新指示调整方案。

## 统一环境

以包含 `code/robot_arm.py`、`camera_server.py`、`simulator/index.html` 的仓库根目录为工作目录。路径随克隆位置变化。当前机器曾使用 COM23、115200/8N1、USB-SERIAL CH340，相机 DirectShow 名称为 `2M`。连接前枚举实际设备，旧端口和上次位置只提供线索。

- `code/robot_arm.py` 是 MicroPython 驱动，`code/pc_control.py` 提供 PCUART。
- `code/pc_session.py` 保持一个串口连接，接受逐行命令并记录回复与照片。
- `camera_server.py` 共享同一相机采集，默认服务为 `http://127.0.0.1:8766`。
- `simulator/index.html` 是整机仿真，`simulator/gripper.html` 是夹爪局部模型，默认服务为 `http://127.0.0.1:8767`。
- HTML 的目标、程序和模型参数用于规划与对照，真实运动通过串口会话执行。默认仿真参考姿态为 X0 Y174 Z120，实际限位搜索、碰撞和失步需要实物核对。

安装 PC 依赖使用 `python -m pip install -r requirements-pc.txt`。先检查已有服务并复用在线摄像头；同一相机保持单个采集进程。需要启动时运行 `python -B camera_server.py`、`python -B simulator/serve.py`。Windows 后台启动采用隐藏窗口并记录 PID。相机需要 FFmpeg，仿真使用仓库内 Three.js 和模型。设备、端口与几何参数可按现场调整。

## 长连接入口

用户希望实时观看时，运行 `python exploration_monitor.py --rotation 180`，或复用已打开的独立监控窗口。默认180°已经过用户方向图确认。窗口通过 MJPEG 和 JSONL 订阅工作，操作说明见仓库 `docs/monitor.md`。

每轮真实观察、判断、下一步和结果都使用 `code/exploration_events.py` 写入中英双语公开摘要，分别选择 observation、interpretation、next_action、result。`--text` 和 `--text-en` 表达同一实际内容。发送指令和控制器回复由长连接入口自动记录。确认停稳后发布 motion_verified，附本轮准确 command 与证据 frame。不要生成占位探索叙述。分析完成再逐条发布该轮真实结论。

使用终端工具的交互 PTY 启动，后续向同一个 session ID 写入。

```text
python -u code/pc_session.py --port COM23
```

连接只打开串口，默认等待2秒让控制器就绪，打开前设 DTR/RTS 为 False。程序使用普通输入循环，避免 Windows Python 3.14 的 `python -i` 在非控制台中进入报错循环。普通管道 stdin 关闭会结束会话，应保持交互终端。

先发送 `G4 S0` 检查回复。使用 `:snapshot` 取得新鲜画面，再用图像工具查看返回的绝对路径。`/api/status` 提供 `healthy`、`frame_age_seconds` 和 `frame_count`。

输入可为单行 G/M 指令或以下本地动作。

```text
:status
:snapshot
:wait 5
:await
:quit
```

JSON 可组合一条指令与等待时间。`settle` 单位秒，允许0至60秒，之后仍需检查画面。较长动作可以分次等待。

```json
{"command":"G1 X-40 Y174 Z120 F10","settle":8}
```

这是语法示例。先确定当前基准和可达空间，再选择目标。每次发送一条运动指令，保持同一驱动实例和端口所有者。超时使用 `:await` 等待原指令回复，结合画面诊断后继续；重新打开串口不能证明旧动作已经完成。

## 自主运动与观察

首次实体探索前，一次核实无人进入运动范围、明确的小步安全路径和操作者能直接切断执行器电源。串口保持有限超时，通信或视觉异常时停止新增动作。这些信息未确认时，先用 HTML 仿真完成三轴小步闭环，并请求用户补齐最少信息。历史 X−140 至 X60 只记录曾执行的目标。回零路径需要现场确认，避免在未知状态自动执行 G28。

1. 获取图像和通信状态，核实本次电机使能与回零状态。画面倒置时按实际对象理解方向，结合小步测试确定机械 X 正负与画面变化的关系。
2. 用户已授权运动、基础边界已确认且回零路径明确安全时，按需执行 `M17` 使能、`G28` 回零。等待回零过程结束并检查画面。状态未知时先解决基准问题，再发送绝对目标。重连后核实状态，避免依赖旧会话记录。
3. 从已知姿态规划移动。XYZ 为毫米，F 为毫米每秒且最小5。先用可观察步长核对方向，再按空间及用户要求扩大范围。自由观察可扫视多个方向，每个目标停留取图，再根据发现调整下一步。历史测试坐标范围需要结合当前几何与现场使用。
4. `ok` 只作为协议回复。2026-11-16 曾观察到回复后画面继续移动。结合距离、速度预留等待，再比较间隔取得的新鲜画面，确认固定背景稳定后继续。视觉观察无法提供精确实测坐标。
5. `M3` 闭合、`M5` 打开夹爪。I/J 是即时角度目标，范围与用途依据当前标定。抓取先观察夹爪与目标的相对位置，小步接近，夹持后观察实际结果。
6. 近处手臂进入运动区域、遮挡、画面过期或通信状态不明时暂停新增动作。处理具体障碍，必要时请用户移开遮挡，恢复后接续原目标。
7. 完成目标后选择合适的停留位置并观察停稳。`:quit` 关闭串口并保留电机状态。`M18` 会使关节失去保持力，按现场需要使用。报告执行范围、观察结果、最后目标和未核实状态。

每轮按 OBSERVE → THINK → ACT → WAIT → OBSERVE → LEARN 推进。记录动作前后图像路径、假设、目标指令、等待依据、画面变化、结论与不确定性到 `.runtime/` 的探索日志。观察阶段保持与显示器、工具和其他设备的间距，未知物体的抓取按用户具体任务处理。无需为完善空间模型延迟已获授权且边界明确的小步实验。

## 协议与开发

用户要求说话时，可用 `python code/pc_speech.py "实际要说的话"` 调用 Windows 已安装的中文 SAPI 语音模型，通过电脑默认音频输出播放。`--voice` 选择已安装声音，`--output` 选择已枚举设备名称的子串。当前电脑默认音频输出为 F240W 显示器音频，中文声音为 Microsoft Huihui Desktop。播报开始、完成和异常会写入同一监控日志，播放返回只说明语音引擎完成，现场是否听见由实际音频设备决定。语音程序可以与逐段机械动作配合，串口仍保持单一所有者。

详细指令见仓库 README 和 `串口通信指令.docx`。已知指令包含 G0/G1、G4、G28、M17/M18、M3/M5、IO 与12V输出。后两者依据用户当前任务操作。当前协议资料缺少急停、位置和运动完成反馈，不猜测其他固件的 G90/G91、M114、G92 等含义。

驱动 pending 防护仅对应尚未收到回复的指令，物理运动需要观察循环补足。仿真原点在肩轴，+Y向前、+Z向上、+X横向。照片重建尺寸存在待标定项，相机17 mm十字孔距来自用户提供。

需要量化图像变化时，可安装 `requirements-vision.txt` 并运行 `python tools/compare_frames.py BEFORE.jpg AFTER.jpg --region X0 Y0 X1 Y1`。选择纹理清楚、人员不遮挡的固定背景区域。它输出局部块匹配的像素偏移与分歧，只作为画面证据。局部背景静止、重复纹理误匹配或独立运动物体均可能影响结论，需要结合连续帧和等待时间判断。

修改驱动保持 MicroPython 兼容和 mip 安装路径有效。修改仿真先运行数学与夹爪检查，再查看浏览器实际加载。实机验证在用户当前授权内执行，如实记录范围。日志与抓帧保存在被忽略的 `.runtime/`。
