# 机械臂辅助调试 MttoRobot 进度

记录日期 2026-11-18，时间按北京时间。

## 阶段结论

1. **现场先明确机械臂的安全范围，Codex 更容易规划出连贯的动作。** 与让 Codex 逐点试探角度相比，由现场人员先给出当前工位各轴正负 20 厘米的净空，再由 Codex 在运动学可达范围内规划路径，可以减少试探性移动，更顺畅地安排低位、左右斜侧和近景取景。
2. **Codex 调参后，桌面搭子的左右转在录像中更明显。** 现场回看与早期人工调试效果的对比显示，调整步态幅度和右转时的左髋相位后，左右转向更容易辨认，尤其是右转时机身转回正面的变化。这是基于实机画面的定性结论，净转角仍待量测。

## 实机进度

当前已跑通机械臂取景、MttoRobot 的 Wi-Fi 动作控制、同步录像和多机位取图。机械臂搭载 USB 相机，镜头朝向桌面的双足机器人。调试使用机械臂串口 `COM25`、相机服务 `127.0.0.1:8768` 和具身探索监控台。相机原始画面按安装方向旋转 180° 后显示。

| --- | --- |

## 识别算法方案（第一版，待实现与验证）

下文的识别目标是镜头里的双足机器人 MttoRobot。现有扫视程序使用光流检查转场停稳，目前的识别进度是已收集多角度素材并确定第一版方案。

你这几张照片够做第一版。**先用胸前的黑色屏幕外框认出桌面搭子，再用光流跟踪机身，用帧差判断哪一部分在动。** 这样机器人静止时也能被认出来，眨眼和手臂摆动也可以分开处理。

| 要解决的问题 | 传统 CV 做法 | 用你照片里的什么特征 |
| --- | --- | --- |
| **这一帧有没有桌面搭子？** | Canny 找边缘，`findContours` 找近似四边形，再对候选区域做透视拉正和模板比对 | 黑色屏幕外框作为主特征，蓝色内框作为辅助，附近的白色机身再做一次校验 |
| **下一帧它在哪？** | 在屏幕外框和机身上取角点，用金字塔 Lucas–Kanade 光流跟踪。有效跟踪点太少就重新检测 | 屏幕外角、白壳转角、可见的螺丝孔。把眼睛和嘴的动画区域排除在跟踪点之外 |
| **是整机动了，还是手脚动了？** | 先看机身锚点相对画面的位移，再按机身对齐相邻帧，在左右臂和脚部 ROI 内分别做 `absdiff` | 机身框整体平移时记录画面位移。对齐后只有某一侧手臂区域仍有明显变化，就标记该侧有局部运动 |
| **大致从哪个方向看？** | 对照不同视角模板，结合屏幕四边形的透视形变、露出的机身侧壁和顶口，输出粗分类 | 正面、左斜、右斜、偏俯视。证据不足时输出 `unknown` |

### 你这几张图怎么用

- **正面全身、正面近景**：作为正面参考。裁出黑色外框和周围一圈白壳，保留原图做检测调试。
- **左斜、右斜**：分别做模板。正面模板匹配弱时，看看侧壁和顶口能不能把方向分出来。
- **顶部、脚掌特写**：用于定义局部观察区。顶部线束容易变形，脚掌又和白桌颜色接近，第一版都可以先从整机识别条件里省掉。

有一个会直接影响结果的条件：**如果 USB 摄像头固定在桌外拍机器人，整机位移和局部动作最好区分。** 如果摄像头也在动，但仍看得见机器人，可以尝试用背景特征估计相机运动。你这里还有上下和前后移动，桌面、显示器和货架会产生不同程度的视差，整幅画面用一次变换补偿后仍可能有残差。第一版可以在快速转场时保留录像，到短停后再重新识别。如果相机装在搭子身上、朝外拍，识别它自身需要有机身部件进入画面。

第一版最值得看的是三个画面：**站着不动能框住、眨眼时机身不报动、单臂一摆能标对侧。** 这三个过了，再拿快速扫视录像看转场后的重识别。
