# 具身实验安全封装

`experiment_safety.py` 为任务书 v1 增加纯软件准入层和 `SafeExecutor` 执行封装，复用原有 COM8 `d.run_segment` / `d.confirm_settled` 及观察臂运动入口。构造和测试不访问硬件；当前未部署到板端，也未启动 S1。旧 `embodied_demo.py` 不能作为本次任务的直接执行入口。

本次人工授权允许增加限制；原始 PWM 窗口、通道、频率、底层限速和回零逻辑保持不变。

- 绿臂单段最大变化为 **5 counts**，来源是已记录的小幅点动。仅绿臂2肩或肘可选一轴，其他轴起点/终点均须在核准参考位。先校验整个目标，再调用原驱动；单调 smoothstep 的所有中间 counts 都位于已校验起终点区间。
- 大臂单段最大 **5 mm**，速度 **F5**。只允许文档实际走过的机位连线，可将连线细分；禁止在整个边界箱内随意选轨迹。连线端点在原凸边界箱内可证明整条直线不越界，但不能证明现场无障碍。新的初始位置和回零后到参考位的路径仍需单独建立可信基准，不能拿仿真原点代替实机状态。
- 每次动作必须完成独立的新鲜停稳窗口检查；尚未完成时不能发第二段。完成后至少间隔2 s；本版保守预算240段、1800 s。预算用尽锁定暂停。
- 授权绑定连接，初始关闭。故障、断线、重启、预算耗尽后锁定，不凭旧授权自行恢复。
- 主机超时、视觉质量不足时禁止发新动作，保留最后输出，不发送回参考位或失能请求。通信不明时不能证明已开始的板端动作立即停止，也不能保证其当前位置；不得把“Hold”写成安全位闭环控制成功。
- 原驱动对硬件级 I²C/PCA 错误的 `release=True` 策略未改，仍可能失去保持力。这一封装无法覆盖物理断电、PCA掉电或底层硬件故障。

`SafeExecutor.check_hardware` 要求UID、I²C、PCA地址、prescale=121、MODE1、底盘/夹爪FULL OFF、六轴参考状态和寄存器互相一致。频率不符会拒绝，不自动修正。回零仅有协议确认不等于已知实测坐标；不得从历史记录猜当前起点。

静态回归：`python -B -m unittest discover -s tests -v`、`node simulator/check_math.mjs`、`node simulator/check_gripper.mjs`。安全测试覆盖未授权拒绝、异常暂停、错误起点/终点/频率、步长、全路径、非试验关节、物理完成门禁、节奏和预算，以及超时/低质量后不释放或回参考位。

软件没有硬件急停能力，也无法替代操作者手边的物理电源开关。
