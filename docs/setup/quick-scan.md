# 快速扫视

在观察臂已经使能、完成归零并停稳在标定观察位 X0 Y164 Z120 时，使用同一个串口会话运行。桌面布置变更后，先复核路线和标定观察位。当前设备为 COM25，USB 摄像头复用 8768 端口，启动时以实际设备为准。

```powershell
python -m pip install -r requirements-pc.txt -r requirements-vision.txt
python -B -u code/pc_session.py --port COM25 --camera http://127.0.0.1:8768 --timeout 12000
```

在终端输入 `快速扫一圈`，也可以输入 `:scan`。默认使用 `demo` 路线。录像收到 USB 相机的新帧后，才开始发送运动指令。关键视角确认停稳后额外停留 0.85 秒。开启会话只连接串口，扫视从标定观察位起步。

扫视前用新鲜画面比对参考图。`demo` 与 `desk` 共用 `.runtime/quick-scan-desk-reference.jpg`，可用 `--scan-reference` 指定原始 JPEG。设置参考时，先在实机确认观察臂停在标定位置，再用同一相机的 `:snapshot` 取原图，并将其放到默认路径。参考图保存在本机的 `.runtime`。监控台和报告用正向视角，预检使用相机原始画面。

| 演示顺序 | 观察位 X / Y / Z（mm） | 转场速度（mm/s） |
| --- | --- | --- |
| 抬升 | 0 / 164 / 130 | 7 |
| 下降 | 0 / 164 / 70 | 到 Z85 用 7，再到 Z70 用 5 |
| 前移 | 0 / 174 / 120 | 经 Z85 恢复高度后前移，新增低位线段与前移用 5 |
| 后移 | 0 / 169 / 120 | 5 |
| 左扫 | -10 / 164 / 120 | 经参考位结束后移用 5，左扫用 7 |
| 右扫 | 17 / 164 / 120 | 7 |
| 回到观察位 | 0 / 164 / 120 | 7 |

与标定观察位相比，演示垂直范围为上 10 毫米至下 50 毫米，前后沿已记录的 Y164 至 Y174 直线往返。新增 Z85 至 Z70 直线通过项目的运动学检查。成片由同一 USB 流导出，保留连续动作和原速。录像链路中断时停止发送后续运动。

当前工位确认了参考位前后、左右、上下各 200 毫米的现场净空。新增拍摄路径逐段通过项目既有运动学检查，并沿用控制器限位。

需要同步演示 MttoRobot 时，在启动串口会话时增加 `--scan-biped <Wi-Fi 调试 URL>` 和 `--scan-biped-config <本机 wifi_debug.json 路径>`。机器人需要已连接、初始化并空闲。镜头到达低位后固定拍摄，机器人运行一轮左右脚各一步的前进步态并交替摆臂。双足控制器回到起始站立指令且脚部区域的连续画面确认停稳后再扫视。镜头从左扫到右时机器人左转，镜头回参考位时机器人右转。双足控制报错或超时会结束本轮。

联动扫视的前进使用 `speed=0.7`、`amplitude=1.5`、`repeat=1`、`swing_arms=True`，两次转向均用 `speed=0.65`、`amplitude=0.9`、`repeat=1`。复现转向时，在启动前按下面的说明加载双足机器人转向预设。

使用 `--scan-profile desk` 可运行桌面五方向取图路线。

| 顺序 | 观察位 X / Y / Z（mm） | 转场速度（mm/s） |
| --- | --- | --- |
| 左 | -10 / 164 / 120 | 7 |
| 右 | 17 / 164 / 120 | 7 |
| 上 | 0 / 164 / 130 | 7，经标定观察位 |
| 下 | 0 / 164 / 85 | 7 |
| 正前方 | 0 / 164 / 120 | 7 |

参数 `--scan-profile cruise` 可选择旧工位的 F7 路线，执行左、上、正前方，输出右和下缺失。它使用对应工位的 `.runtime/quick-scan-cruise-reference.jpg`，路线见 [观察臂巡航记录](../archive/historical_poc/green_arms/embodied-demo.md#多视角巡航)。

转场按距离和速度估算等待下限，随后检查间隔 0.6 秒的两张新鲜画面，确认视角确实变化并停稳后继续。清晰度检查由拉普拉斯方差估算；低于阈值补拍一次，若仍模糊则在报告中标记并继续。UART 异常、画面过期或停稳无法确认时停止发送后续动作，保留已完成的结果和最后核验的目标。

桌面机位从归零方向进入和从下方返回时，实测同一指令目标的画面相差约 9 像素。桌面起点预检的特征位移容差为 12 像素，转场停稳仍要求相邻帧位移低于 0.8 像素。坐标为控制器目标，启动前仍需核对实际工作台布置。

每轮在 `.runtime/quick-scans/` 下保存各方向的正向关键帧和 `report.json`。演示的同时间戳 `-usb` 目录包含原始 `vision.mkv` 和可播放的 `quick-scan.mp4`。报告计时从扫视预检到最后停留结束，录像包含前后余量。归零和标定在准备阶段完成。监控台实时读取同一会话的 UART 事件和双语摘要。

2026-11-18 桌面实测覆盖全部五个方向。先用 F5 验证新增转场，混合速度首轮 35.68 秒。全程 F7 复测 28.11 秒，各方向均首次取图清晰，最后停回标定观察位。

同日完成同步录像演示。先在低位拍摄 MttoRobot 一轮原地摆臂，再完成前后与左右转场。成片为连续 USB 第一视角，1280×720，46.4 秒。

之后在 Z70 低位复录前进摆臂与同步转向，成片 61.84 秒。前进段双脚完整入镜，脚部停稳后恢复机械臂扫视。左转与右转分别在横扫与回位时启动，结束后回到标定观察位。

## 双设备动态演示

先确认机械臂已停在标定观察位 `X0 Y164 Z120`。按 MttoRobot 的说明加载转向预设，确认双足机器人已初始化并空闲。首次进入 Wi-Fi 调试模式时，可先发送 `home`，等 `GET /status` 返回 `initialized=true` 和 `state=idle`。转向预设重启后需重新加载。 [MttoRobot Wi-Fi 调参说明](https://github.com/FreakStudioCN/MttoRobot/blob/main/docs/WIFI_DEBUG.md#恢复联动录制的转向参数)

在机械臂仓库根目录操作。电脑需要带 Tk 的 Python、开头列出的 Python 依赖，以及 PATH 中可调用的 FFmpeg 和 FFprobe。若 USB 相机服务未运行，先打开一个 PowerShell 窗口启动服务。将 `2M` 替换为本机摄像头名。已有 8768 端口的同一相机服务时直接复用。

```powershell
python -B camera_server.py --port 8768 --device '2M' --width 1280 --fps 10 --reconnect
```

在另一个窗口启动具身探索监控台并保持窗口可见、处于实时模式。相机按实拍安装方向旋转 180°。 [监控台说明](monitor.md)

```powershell
python exploration_monitor.py --camera http://127.0.0.1:8768 --rotation 180 --no-skeleton
```

在新的 PowerShell 窗口启动串口会话。三个变量须按本机替换。示例配置路径假设两个仓库在同一父目录。两台设备的串口用途不同，此处填写观察机械臂的串口号。

```powershell
$armPort = 'COM25'
$robotUrl = 'http://192.168.137.123:8080'
$robotConfig = (Resolve-Path '../MttoRobot/firmware/wifi_debug.json').Path
python -B -u code/pc_session.py --port $armPort --camera http://127.0.0.1:8768 --timeout 12000 `
    --scan-biped $robotUrl --scan-biped-config $robotConfig
```

首次运行或工位画面改变时，先确认标定机位停稳。在串口会话用 `:snapshot` 获取原始 JPEG，将它复制为 `.runtime/quick-scan-desk-reference.jpg`，或用 `--scan-reference` 指向核实过的原图。随后在会话中输入 `:dynamic` 或 `双设备动态演示`。

入口先将机械臂准备到左侧起拍位。USB 原画与具身探索监控台录屏收到新帧后，第一段运动即为镜头横扫与双足左转，随后在镜头回正时同步右转。接下来在低位拍交替摆臂、后退及双臂抬放，再拍前后机位变化和近景摆臂。两设备只在已验证的前两段转场同时运动。

| 顺序 | 机械臂目标 X / Y / Z（mm）与速度（mm/s） | 双足机器人动作 |
| --- | --- | --- |
| 准备左侧起拍位 | −10 / 164 / 120，F7 | 站立 |
| 横扫 | 17 / 164 / 120，F7 | 左转，速度 0.65、幅度 0.9、1 轮 |
| 回扫 | 0 / 164 / 120，F7 | 右转，速度 0.65、幅度 0.9、1 轮 |
| 抬升、下降、低位 | Z130 和 Z85 用 F7，Z70 用 F5，X0 / Y164 | 站立 |
| 低位演示 | 保持 X0 / Y164 / Z70 | 交替摆臂速度 0.8、1 轮，后退速度 0.7、幅度 1.5、1 轮，然后以速度 0.8 双臂抬起和放下 |
| 回升、回正、前移 | 依次到 0 / 164 / 85（F5）、0 / 164 / 120（F7）、0 / 174 / 120（F5） | 站立 |
| 近景摆臂 | 保持 X0 / Y174 / Z120 | 交替摆臂速度 0.8、1 轮 |
| 后移、结束 | 依次到 0 / 169 / 120、0 / 164 / 120，F5 | 站立 |

表中转向均关闭摆臂。脚踝与髋关节的八帧角度由 MttoRobot 的预设提供，两个转向名义周期均为 1600 ms。每段观察臂移动按距离和速度等待，并经过画面停稳检查。移动段确认停稳后，额外等待 0.18 秒。

实时预览用黑色胸屏外框、蓝框及周围白壳定位机身。光流跟踪用外框边缘与相邻外壳，机身对齐后的帧差分别标注左右臂活动区。屏幕内部动画不参与手臂判定。延迟、遮挡和视角变化会影响粗分类，转场段保留原画并暂停分析，停稳后重新定位。

每轮产物位于 `.runtime/dynamic-demos/` 的同一时间戳目录。原始 USB 轨道为 `recordings/vision.mkv`，同步后的正向画面和具身探索监控台录屏分别为 `recordings/dynamic-usb.mp4`、`recordings/dynamic-desktop.mp4`。`report.json` 记录实际动作及机位关键帧，`overlay.jsonl` 保留视觉输出。两路按主机记录时钟对齐。
